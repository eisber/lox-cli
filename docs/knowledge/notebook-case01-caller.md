  rule, executable, address, port, interface, service and security-filter checks
  do not prove absence of effective third-party WFP bypass/callouts.

Do not delete these refusals or replace them with caller/file booleans. Complete
and independently review those mechanisms before any native invocation. The
backend currently cannot pass either boundary; unused effect branches are
implementation scaffolding, **not native-tested or operational**.

## Future parent integration prerequisites

The private `NotebookCase01` API is not an execution recommendation. It requires
a newly reviewed exact source composition, byte-pinned case/master fixture and
contracts, new parent/reviewer/owner receipts, a privately supplied runtime
profile identity, actual bridge identity/source pins, real UTC admission/deadline,
and an existing approved private evidence root outside repositories. Every
exchange requires an explicit deadline at most 25 seconds; the complete case is
at most 20 minutes including cleanup reserve.

Each visual selection must be a newly byte-pinned external parent/vision receipt
bound to the actual screenshot, owned identity and exact fixture source route.
No coordinate is generated from a rectangle center/fraction. Missing selection
returns `VISUAL_SELECTION_REQUIRED`; unknown/ellipsis never means OFF.

Any timeout parks the case with remote completion UNKNOWN and forbids reconnect,
retry and remote cleanup. Other terminal events permit only separately authorized
freshly guarded graceful owned cleanup, never behavior resumption or forced kill.
Actual process absence and unchanged bytes remain independent cleanup evidence.

The transport's published CRLF bytes and LF-only equivalent are explicitly
recognized at import. External admission must still pin the **actual raw bytes**
of every runtime source; line-ending equivalence is not inherited approval.
